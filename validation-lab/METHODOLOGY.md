# Methodological limits and outstanding validation

No real FIT files or physiological experiment results were used. No threshold recommendations are justified yet.

FIT reconstruction is separate from the engine. CRC errors reject files. All message types and developer fields are retained as decoded fields. First duplicate timestamp wins and is flagged; out-of-order records sorted and flagged. No carry-forward or interpolation. Missing one-second slots have null sensors. Explicit timer events apply at their timestamp; absent timer events assume running and mark approximation. First record anchors minute phase: device compute may have begun earlier. Fractional-second recordings and late events need manual review. Multisport/non-cycling sessions are unsupported. A seven-day expansion limit rejects extreme/corrupt timestamps. Missing power differs from zero for classic variants, but current compatibility intentionally treats both as zero when HR exists.

A comparison_candidate has regular timestamps and timer information, not proven exact device replay. Approximate data can support exploratory comparisons but cannot establish a Monkey C defect. Less than 60 active seconds or >20% missing sensor seconds marks insufficient. These are importer research flags, not production criteria. Results for insufficient files remain exploratory, not automatically usable. Exact comparison needs captured identical compute() sequences and matching algorithm version, timer phase, device Float arithmetic and recorded state. Developer fields update after minute boundaries and can retain stale values.

Source sums are preserved by bucket compression, but distributions within a bucket are lost. Minute diagnostics expose an UNCOMPRESSED steady-second split and additive power contributions; after compression these shares need not equal production bucket shares. Per-minute drift contributions are not uniquely additive. Current UI shows only RIDE drift trajectory; LAST60 final result is in JSON/summary. The report supplies per-model minute reasons, differences and individual minute traces; statistical cohort plots, independently annotated steady segment evaluation, robust automatic ride-type classification and physiological false-rejection rates remain future work. Never infer false rejection just from another filter including a minute.

Current mean-power Pw:HR, positive-only, elapsed-active-time split, valid-time split and exploratory HR/P regression use different inclusion rules. Regression is a simple unadjusted slope, not an HR = intercept + power + time causal model. No Normalized Power, temperature adjustment or uncertainty model is inserted into production. OFAT experiments do not measure parameter interactions. Lower or smoother values are not evidence of better physiology. Compare common input segments to distinguish formula bugs from methodology and selection bias. User-selected steady segments and stable external workload are needed before physiological conclusions.

Official Personal API adapter is implemented with mocked transport tests, not yet verified against this user's account. The key must be entered locally with lab.ps1 auth. FIT download/archive and analysis are resumable but API pagination is offset-based, so activities created during a sync can move page boundaries; rerun sync. Existing manifest originals are immutable in ordinary incremental sync; detecting server edits requires deliberate manifest entry removal after backing it up. No destructive archive command exists. Rate limits are not assumed to be a known numeric quota. Secrets are DPAPI-protected only on Windows; environment key fallback is process-local responsibility. Reports contain private data; keep them local.
