# Исправления offline FIT timer policy — 2026-10-31

Область: только validation-lab, приложение и формула DRIFT не меняются.

normalize теперь явно помечает неизвестное начальное состояние таймера:
если до первого RECORD нет распознанного start/stop, running до первого события
остаётся допущением. Отсутствие событий — также допущение. Quality не может быть
comparison_candidate без предупреждения; возможны approximate или insufficient.
Первый известный stop до/на первом RECORD задаёт остановленный таймер однозначно.

Разные event_group не объединяются. Для диагностического proxy детерминированно
выбирается одна группа (неизвестная группа после известных, затем строковый порядок
идентификаторов); при нескольких группах всегда timer_ambiguous=true и issue.
Это не установление authoritative group. Смешанные missing/known group также
неоднозначны. Для строгой проверки такой поток непригоден.

Противоречивые start/stop одной группы в один timestamp имеют явную политику
stop wins и ambiguity flag. Порядок входного списка больше не меняет результат.
Raw events сохраняются в messages read_fit без замены исходных временных меток.
Новые quality-поля: timer_ambiguous, timer_group, timer_policy.

Регрессии: unknown prefix, известный initial stop, разные группы и перестановка
одновременных событий, конфликт внутри одной группы, legacy события без group.
Все прежние тесты сохраняются. Флаг comparison_candidate по-прежнему не означает
доказанной идентичности FIT и compute callbacks.

Результаты повторной инвентаризации — в timer-policy-verification.json.
Полные отчёты с персональными данными хранятся локально, в Git не публикуются.
