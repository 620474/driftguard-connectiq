## DRIFT

В дополнение к прежним gates steady требует CV положительной секундной мощности
при валидном HR не выше 30%: E[P²] ≤ 1.09 × E[P]². Это инженерный фильтр,
не физиологически валидированный порог. Чередование 100/300 W больше не проходит.
Нулевая мощность по-прежнему уменьшает valid seconds, а не входит в CV.
HR вне 1…300 и мощность вне 0…10000 исключаются. Compatibility сохраняет
свою отдельную политику: при валидном HR отсутствующая мощность считается нулём.

Paused seconds не добавляются. После resume минута, содержащая первую новую
running sample, отклоняется; следующие три ровные минуты проходят recovery.
Сетка минут остаётся по 60 running samples, поэтому calibration может её сверить.
Оба фильтра действуют одинаково на RIDE и LAST 60. Последний валидный RIDE
и номер минуты сохраняются отдельно; это время последнего разрешённого
расчёта, а не время последней steady sample.

**Существенное ограничение:** на 123 FIT из проверенного архива новые gates
оставили 1291 steady minute вместо 2461; итоговых VALID RIDE/LAST60 стало 0/0
вместо 8/5. Это снижение доступности, а не доказательство большей точности.
Не выбирать порог по максимальному числу VALID на этом же архиве. До выпуска
нужны заранее размеченные ровные нагрузки и отдельные контрольные поездки.

## AUTO EXP и интервалы

AUTO EXP сохраняет сегменты от 20 s без верхней отсечки на 240 s.
Сегменты от 240 s помечаются sustained; это описание длительности, не
автоматическое определение намерения спортсмена. Поэтому длинная ступень
мощности может быть сохранена как sustained даже если это обычный темп.
Порог окончания — максимум прежнего frozen baseline gate и 70% среднего
первых трёх confirming samples (целочисленное округление вниз). Это предотвращает
растягивание короткого всплеска на лёгкий хвост после очень низкого baseline.
Вход 180 W, +15% и +30 W, подтверждения 3/5 s и split после 120 s сохранены.
Спринты короче 20 s остаются вне контракта AUTO EXP; их нельзя объявлять
«не происходившими». В Python они доступны как discarded short candidates.

Идентификатор completion монотонный на всю активность и переживает повторный
workout start и смену источника. Reset активности обнуляет его. Ранний переход
в manual/workout по-прежнему начинает новый явный сегмент; незакрытый AUTO
не выдаётся за завершённое повторение.
Средняя мощность явного сегмента считается только по valid power seconds,
включая нули. Неполнота/пауза помечается отдельно, HRR для такого сегмента
не начинается. Полная потеря мощности также сохраняет duration/coverage,
с отсутствующим mean power, а не с выдуманным средним.

## Production FIT schema 2

ID 0…9 сохраняют имена и типы. RECORD занимает 11 B, SESSION 14 B.
Старые SESSION snapshots ID10…13/20 больше не создаются: last effort и HRR
восстанавливаются из REP. Это намеренное изменение схемы; старые FIT не меняются.

| ID | Поле | Тип / message | Значение |
|---|---|---|---|
|14|dg_rep_id|uint16 / RECORD|Монотонный ID completion, 0 до первого события|
|15|dg_rep_w|uint16 / RECORD|Средняя валидная мощность, округлена вниз; FIT invalid при отсутствии|
|16|dg_rep_s|uint16 / RECORD|Running duration, ограничена 65534|
|17|dg_rep_src|uint8 / RECORD|1 AUTO, 2 MANUAL, 3 WORKOUT|
|18|dg_rep_hrr|sint16 / RECORD|Strict HRR60; −32768 означает недоступно|
|19|dg_rep_evt|uint8 / RECORD|1 completion, 2 strict HRR, 3 active HRR|
|21|dg_rep_hrr_active|sint16 / RECORD|Active HRR60; −32768 означает недоступно|
|22|dg_schema_version|uint8 / SESSION|2; включает алгоритмический контракт этой версии|
|23|dg_last_valid_drift|float / SESSION|Последний разрешённый RIDE; −9999 если не было|
|24|dg_last_valid_minute|uint16 / SESSION|Running minute последнего разрешённого RIDE, 0 если не было; cap 65534|
|25|dg_rep_count|uint16 / SESSION|Число опубликованных completion для контроля потерь RECORD|
|27|dg_rep_quality|uint8 / RECORD|Биты: 1 partial/pause, 2 missing power, 4 sustained, 8 duration clipped|
|28|dg_rep_valid_s|uint16 / RECORD|Число секунд с мощностью; cap 65534|
|29|dg_rep_recovery_w|uint16 / RECORD|Средняя мощность 60 s восстановления; FIT invalid до завершения|
|30|dg_rep_end_s|uint32 / RECORD|Число наблюдённых running callbacks от reset до последней sample сегмента; подтверждение может прийти позже|

Итого production **32 B RECORD / 23 B SESSION**. ID не переиспользуются
в пределах сборки. После 65534 повторений запись отключается, ID не оборачивается.
Все поля сбрасываются при reset; ошибка записи отключает recorder без падения
расчётов. Числовые DRIFT-поля при отсутствии результата получают −9999;
потребитель всегда проверяет matching state (VALID=4). Нулевой drift допустим.
Устаревшие значения старых схем всё равно требуют gating по состоянию.

События held, не очередь: следующий completion/HRR заменяет текущий event.
Редкая запись FIT может пропустить событие. Decoder проверяет начальный ID,
разрывы и session count, сообщает orphan HRR; восстановление не гарантировано.
HRR привязан к completionId. Strict/active отличаются пределами 50%/90%
мощности усилия на каждой recovery sample; это engineering gates. Оба используют
3 s end HR и 3 s HR на +60 s. Полный экран показывает active HRR и recovery W.

## Calibration и offline

Calibration создаёт только base ID0…9 + diagnostic ID10…22:
**32 B RECORD / 24 B SESSION**. Production REP extras исключены аннотацией.
Algo version=2, config CRC32=3866173107. Reject reason 2 теперь включает
power band, внутриминутную вариативность и resume; Python различает эти причины
в отчёте. Конфигурационная строка — в driftlab/calibration_config.py.

driftlab.auto_exp — порт текущего AUTO EXP v2; driftlab.auto_efforts остаётся
отдельным исследованием старых balanced/responsive/conservative кандидатов.
CLI анализ сохраняет auto_exp_offline отдельно от fit_repetitions. Незакрытый
хвост не становится completed effort при offline EOF. Все входы — сетка 1 Hz;
Python float64 не равен побитно Monkey C Float.

Decoder атрибутирует реальные REP только при совпадении application_id production.
Неизвестные/нулевые ID помечаются unverified. Отсутствие полей — unavailable,
не доказательство отсутствия усилий. Простой application_id не доказывает commit;
для новых записей проверяйте schema version, для calibration — version/config.
Исследовательские HTML/Markdown получают числа из текущего research.json,
поддерживают --data и пустой набор; сохранённые исторические отчёты не переписываются.

## Границы проверки

Архив — ретроспективная проверка одного спортсмена, без независимой полной
разметки всех усилий. Count 1547 против 2111 не является precision/recall.
В новых событиях 42 sustained и 10 partial. Контрольные длинные блоки сохранены.
Физический Edge и фактическое сохранение нового FIT на устройстве требуют
отдельной проверки; симулятор и unit tests её не заменяют. Публикации релиза нет.
