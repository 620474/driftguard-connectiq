# Протокол сравнительного исследования моделей

Цель: сравнить текущий oracle с фиксированным EF-эталоном и HR-регрессией;
текущий AUTO EXP — с относительным FTP-кандидатом; end HRR — с отдельным peak HRR.
Это offline-гипотезы в validation-lab. Monkey C, FIT schema и публичные метрики
приложения этот этап не меняет. Параметры не выбираются по числу VALID на архиве.

## Воспроизведение

```powershell
python -m pip install ./validation-lab
cd validation-lab
python -m unittest discover -s tests -v
python -m driftlab.model_study --archive FIT_DIR --manifest manifest.json --output NEW_DIR --cache CACHE_DIR --ftp-history history.json
python -m driftlab.model_report --input NEW_DIR
```

Без --ftp-history расчёт даёт явные сценарии чувствительности, без приписывания
их спортсмену. Дополнительные значения задаются --ftp-scenarios (целые W).
History — JSON array с `since` (ISO date), `ftp` и необязательным описанием точности
даты. Смена месяца не доказывает точный день; сравнивайте соседние значения FTP.
Текущий FTP нельзя молча переносить назад на весь сезон. Значение, записанное в
session/zones_target FIT, может расходиться с предоставленной историей настроек.

Manifest содержит files: file, sha256, bytes, start_local; activity_id опционален.
Все размеры и SHA проверяются до анализа. Default input — fresh fitdecode с CRC;
версионированный cache требует source SHA и hash функций read_fit/normalize.
Кэширование не доказывает равенство FIT-сетки и live compute. Полный отдельный
аудит CRC архива также выполнен. Plan сохраняет базовый commit, fingerprint
модельного кода, входных файлов и факт незакоммиченного дерева при расчёте.

## Фиксированные кандидаты

- DRIFT: текущий RIDE/LAST60 из oracle; EF первых 20 post-warmup минут (16–35)
  против последних 10 минут при сопоставимой мощности; HR ~ EWMA(power) + time.
  EWMA tau 0/40/60 s, пары с положительной мощностью, минимум 48 seconds/minute,
  40 поддержанных минут, минимум 30-min span; после resume исключаются 180 running s.
  HR/паузы/пропуски не интерполируются. При minute-power variance <1 W² применяется
  только time slope; при |power-time correlation| >0.98 полный fit отклоняется.
  HAC(3), Bartlett weights, normal ±1.96 interval — модельная неопределённость,
  которая не учитывает все датчиковые и физиологические ошибки. Интервалы не
  являются доказательством причинного дрейфа. Сохраняется расчёт на common support
  текущих steady-минут; разные наборы минут нельзя сравнивать как одну формулу.
- Relative AUTO: baseline 60 s только вне усилия; entry max(0.60 FTP, 1.20 baseline,
  baseline +0.10 FTP), exit max(1.08 baseline, baseline +0.05 FTP, 0.70 entry power).
  Подтверждения 3/5 s, min20 s, без split и верхней отсечки. EOF не создаёт завершение.
- Peak HRR: минимум 180 s усилия, максимум trailing3 HR в 0…15 s после конца,
  60 s после выбранной точки; все recovery samples от конца усилия ≤0.40 FTP.
  Обе HRR-дефиниции рассчитываются на одинаковых границах; current/candidate
  boundaries сохраняются отдельно. Следующее усилие, pause, gap и EOF цензурируют
  окно. Порог длительности и мощности — инженерные параметры, не доказанный
  критерий физиологической достаточности. Поиск максимума сам может дать смещение.

## Проверка и независимая разметка

15 фиксированных синтетических протоколов, три tau: известные linear4 bpm/h при
разной длительности, шаги мощности, повторы, подъём, спринты, холмы, пауза, gaps,
нелинейный HR и температурная прибавка. Seed фиксирован; это ограниченный набор,
а не Monte-Carlo оценка надёжности. Генератор расписаний задаёт интервалы до
детекторов; цель planned_effort явно отличается от любого изменения мощности.
Matching — maximum-cardinality one-to-one при IoU≥0.5, timing error отдельно.

Для реальных данных blind-review.html показывает только входные power/HR,
без результатов моделей. Экспорт CSV: sha256,start,end,label,source. Source должен
быть manual_blind; label reviewed объявляет полный просмотр [0,wall_seconds−1],
label effort — границы намеренного рабочего интервала. Затем повторить запуск с
--labels labels.csv. Без полного просмотра отрицательные интервалы не размечены,
поэтому precision/recall не рассчитываются. Декларация источника не является
автоматическим доказательством независимости разметчика. Для неоднозначных поездок
нужны план/журнал тренера; круг или подъём сам по себе не является planned effort.

Архив разделён 80/20 по времени (98/25); модели не выбираются по поздней группе.
Архив уже исследовался раньше, поэтому это ретроспективная проверка, а не чистый
holdout и не внешняя валидация. Реальные precision/recall и истинный физический
дрейф неизвестны. В FIT нет достаточной последовательности размеченных work/rest
laps для независимой истины; наличие step index само по себе не помогает.

## Результаты и границы

Обезличенный снимок: [MODEL_COMPARISON_RU.md](MODEL_COMPARISON_RU.md).
Полные локальные результаты содержат личные данные; они, исходные FIT и FTP history
в Git не добавляются. Ни один кандидат не выбран для production. Больше численных
ответов или интервалов не означает большей точности.
Зависимость HR-метрик от протокола: [Buchheit](https://pmc.ncbi.nlm.nih.gov/articles/PMC3936188/).
Fixed reference в беге: [Smyth et al.](https://pmc.ncbi.nlm.nih.gov/articles/PMC9388405/).
HAC: [Newey & West](https://doi.org/10.2307/1913610).
Эти источники мотивируют подходы, но не валидируют наши пороги и алгоритмы на велосипеде.
